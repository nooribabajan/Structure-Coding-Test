Chapter Development Master Workflow

Chapter 04 سے اخذ شدہ — Chapter 05 اور آئندہ Chapters کے لیے Reusable Master Procedure

Phase 01 — Master Reference & Architecture Lock

  • Approved Master Architecture: Chapter 01 کی approved architecture کو master reference ماننا؛ Chapter 04 کی approved improvements شامل کرنا؛ غیر ضروری architecture redesign نہ کرنا۔
  • Repository Structure: Repository Root کے تحت Memory/ (Consolidated Master Version) اور Chapters/ parallel top-level sections رہیں۔

Phase 02 — Academic Source & Syllabus Audit

  • KPK Biology syllabus، Curriculum/SLOs، Grade/Class requirements، متعلقہ textbook اور examination-oriented learning outcomes collect کرنا۔
  • تمام definitions، concepts، explanations، processes، examples، comparisons، diagrams، tables، formulas/equations، terminology اور examination points collect کرنا۔
  • KPK requirements کو OpenStax اور معتبر international Biology references سے cross-check کرنا۔

Phase 03 — Topic Inventory

  • Topic → Sub-topic → Concept → Learning Point → Visual Requirement → Practice Requirement → Practical Requirement کی مکمل inventory بنانا۔
  • Missing / Duplicate Audit: topic، sub-topic، concept، visual یا requirement کے missing/duplicate ہونے کی جانچ۔

Phase 04 — Learning Sequence Design

  • Academic sequence coding سے پہلے بنانا: Foundation → Concept → Mechanism → Process → Application → Comparison → Integration → Practice → Revision → Test۔
  • Learning steps کی تعداد content کی ضرورت کے مطابق رکھنا؛ کسی fixed number کا پابند نہ ہونا۔
  • Opening sequence کو آخر میں دوبارہ audit کرنا۔

Phase 05 — Page / Pagination Planning

  • ہر learning step کے لیے heading، explanation، visual، example، interaction، key point اور next-step relationship plan کرنا۔
  • Page length، mobile readability، visual/text balance، spacing، headings اور visual placement کا final audit کرنا۔

Phase 06 — Visual Atlas Development

  • ہر topic کے لیے required visuals کی مکمل فہرست بنانا۔
  • ہر visual کو international-standard Biology visuals کے مقابلے میں academic accuracy، labeling، clarity، completeness اور educational usefulness کے لحاظ سے check کرنا۔
  • تمام visuals کو آپس میں compare کرنا: duplicate، missing، inconsistency اور text-only concepts کی جانچ۔
  • Final Visual Atlas کو Syllabus → Topics → Learning Steps کے ساتھ cross-match کرنا۔

Phase 07 — HTML Integration

  • Approved architecture میں academic content insert کرنا؛ architecture کو غیر ضروری طور پر redesign نہ کرنا۔
  • ہر step میں academic content، visual، navigation اور interactions درست جگہ integrate کرنا۔
  • Previous، Next، Go To، Step indicators، Search، Visual Atlas، Chapter Test، Practical اور Practice کی integration check کرنا۔

Phase 08 — Practical Work

  • Practical Work کو independent function/modal رکھنا۔ Practical کھولنے یا بند کرنے سے current learning step تبدیل نہیں ہونا چاہیے۔
  • Practical میں objective، materials، procedure، observation، result، interpretation اور ضروری safety/important notes check کرنا۔

Phase 09 — Practice System

  • تمام اہم learning areas کو practice questions سے cover کرنا۔
  • غلط جواب پر لازماً: Your Answer → Correct Answer → Why/Explanation → Revision Topic → Relevant Learning Step۔
  • ہر question کی Question → Topic → Learning Step mapping برقرار رکھنا۔
  • Practice result میں score، correct، incorrect، unanswered، wrong answers، correct answers اور revision topics functional ہونا۔

Phase 10 — Responsive / Modal UX

  • Long modal میں Close X viewport کے ساتھ accessible رہے؛ user کو اوپر scroll نہ کرنا پڑے۔
  • Content اپنی جگہ scroll ہو، Close control ہمیشہ accessible رہے۔
  • Desktop، tablet اور mobile پر width، height، text، buttons، modal، X، tables اور visuals check کرنا۔

Phase 11 — Functional JavaScript Audit

  • JavaScript syntax = PASS۔
  • تمام required functions کی موجودگی اور actual behavior test کرنا: Practical، Practice، Search، Navigation، Modal، Test، Visual Atlas، Go To اور Step engine۔

Phase 12 — Navigation Audit

  • Step-by-step navigation اور reverse navigation دونوں test کرنا۔
  • Random steps سے Go To navigation، currentStep اور content state verify کرنا۔
  • Opening sequence اور ہر modal کی Open → Use → Close → Return to Same Step sequence test کرنا۔

Phase 13 — Content Integrity Audit

  • KPK Syllabus ↔ Chapter Topics cross-check کرنا۔
  • International academic references کے مقابلے میں missing concept، incorrect concept، terminology، sequence اور oversimplification چیک کرنا۔
  • Chapter کے اندر duplicate concept، duplicate explanation، duplicate visual اور contradictory statements چیک کرنا۔

Phase 14 — Visual + Content Cross Audit

  • ہر اہم concept کے لیے Topic → Teaching Text → Visual → Practical → Practice → Revision → Test learning chain مکمل ہونا چاہیے۔

Phase 15 — Final UX Audit

  • Page adjustment، long/short pages، spacing، headings، visual placement اور mobile readability دوبارہ check کرنا۔
  • Opening sequence، closing sequence، floating controls، X، navigation اور buttons دوبارہ audit کرنا۔

Phase 16 — Final Code Audit

  • HTML structure، CSS، Responsive CSS، JavaScript syntax، functions، currentStep، Navigation، Search، Visual Atlas، Practical، Practice، Chapter Test، Modals اور Close controls کا مکمل technical audit۔

Phase 17 — Final Academic Audit

  • ہر KPK SLO کے سامنے Chapter Topic، Learning Step، Visual، Practice، Revision اور Test mapping بنانا۔
  • Missing؟ Duplicate؟ Weakly covered؟ Only mentioned but not taught؟ — ان چاروں سوالات کے واضح جواب لینا۔

Phase 18 — Final Audited Version

  • تمام checks PASS ہونے کے بعد Chapter XX — [Name] FINAL AUDITED فائل تیار کرنا۔
  • Final audited version کو workflow validation reference بھی سمجھنا۔

Chapter 04 سے حاصل ہونے والے خاص Lessons

  • Practical کو chapter navigation سے isolate رکھنا ہے۔
  • Practice میں غلط جواب → Correct Answer → Revision Topic لازمی ہے۔
  • Long modal میں Close X ہمیشہ accessible ہونا چاہیے۔
  • Visual Atlas کو syllabus/topic coverage کے ساتھ audit کرنا ہے۔
  • Page length اور opening sequence final stage پر دوبارہ audit ہونے چاہئیں۔
  • JavaScript function کی موجودگی کافی نہیں؛ actual behavior test کرنا ہے۔
  • Syllabus audit صرف chapter title matching نہیں؛ SLO/sub-topic level پر ہونا چاہیے۔
  • Visuals کو پہلے آپس میں compare کرنا ہے، پھر international standard سے۔
  • Coding سے پہلے academic sequence مکمل کرنا ہے۔
  • Approved master architecture کو preserve کرنا ہے۔
